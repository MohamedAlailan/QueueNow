# QueueNow API

Laravel 12 REST API for persistent queue management, employee authentication, and waiting-time estimation. The API is the source of truth for services, ticket numbering, state transitions, and queue history.

## Responsibilities

- Generate unique ticket numbers per service and queue date inside transactions.
- Enforce the ticket lifecycle and serialize queue mutations through service-row locks.
- Authorize employee actions against the employee's assigned service.
- Authenticate employees using hashed passwords and expiring, revocable Sanctum tokens.
- Protect visitor tracking and cancellation with ticket access capabilities.
- Build validated inference features from operational data and return explicit estimate sources.

## Requirements

PHP 8.2+, Composer, and the standard Laravel extensions, including mbstring, XML/DOM, curl, and PDO. Install `pdo_pgsql` for PostgreSQL or `pdo_sqlite` for SQLite. CI uses PHP 8.3 and SQLite.

## Setup

Run from this directory:

```sh
composer install
cp .env.example .env
php artisan key:generate
```

Configure the following values before migrating:

| Variable | Purpose |
| --- | --- |
| `APP_KEY` | Installation-specific key generated by Artisan |
| `APP_URL` | API origin; typically `http://127.0.0.1:8000` locally |
| `APP_TIMEZONE` | Clinic timezone for daily queues and clock features; defaults to UTC |
| `DB_CONNECTION`, `DB_*` | PostgreSQL connection, or SQLite with an absolute database path |
| `AI_SERVICE_URL` | Private inference origin; defaults to `http://127.0.0.1:8001` |

For SQLite, create `database/database.sqlite` and set its absolute path as `DB_DATABASE`. The supplied `.env.example` defaults to PostgreSQL.

On a new development database:

```sh
php artisan migrate --seed
php artisan employee:credentials staff@example.com --service=1 --name="Clinic Staff" --available
php artisan serve --host=127.0.0.1 --port=8000
```

Replace the service ID with an existing service. The command prompts for a password of at least 12 characters and creates or updates the employee by email. Without `--available`, that employee is marked unavailable. Availability represents configured staffing, not a logged-in session.

The sample seeders create General Consultation, Dental, Pediatrics, and example employees without credentials. They are for initial setup and are not idempotent. Existing installations should run `php artisan migrate` without reseeding.

## API overview

All endpoints are prefixed with `/api/v1`. Send `Accept: application/json`.

| Area | Endpoints | Access |
| --- | --- | --- |
| Service catalog | `GET /services`, `GET /services/{id}` | Public |
| Ticket creation | `POST /tickets` | Public; returns a one-time visitor capability |
| Ticket tracking / cancellation | `GET /tickets/{id}`, `PATCH /tickets/{id}/cancel` | `X-Ticket-Token`; cancellation only while `WAITING` |
| Employee authentication | `POST /employee/login` | Email and password; rate limited |
| Employee session | `GET /employee/me`, `POST /employee/logout` | Bearer token |
| Assigned queue | `GET /employee/queue`, `GET /services/{id}/waiting-list` | Assigned employee |
| Queue actions | `POST /services/{id}/next`, `POST /tickets/{id}/start`, `/done`, `/skip` | Assigned employee |
| Service administration | `POST /services`, `PATCH /services/{id}` | Authenticated `ADMIN` |

See the [full contract](../docs/INTEGRATION.md#api-contract) for response shapes, state transitions, and error codes. Employee tokens expire after 12 hours; logout revokes the current token. Do not expose visitor capabilities or authentication tokens in public logs.

## Waiting-time estimation

The inference server lives in [`ai-service/`](ai-service/). Follow the [AI setup and feature definitions](../docs/INTEGRATION.md#ai-service) to install its pinned dependencies and configure service classes, duration, and staffing.

The estimator uses actual `started_at - created_at` history and Monday-based weekday encoding. Missing model inputs or inference failures fall back to a labeled capacity estimate when staffing and duration are known; otherwise the estimate is unavailable. Existing services receive no guessed AI configuration.

After environment changes, run `php artisan config:clear`, or rebuild the deployment configuration cache.

## Verification

```sh
php artisan test
```

Tests use in-memory SQLite and cover lifecycle rules, service boundaries, authentication, visitor capabilities, daily numbering, configuration validation, timestamps, and AI features/failures. PostgreSQL lock contention still requires verification against the deployment database.

For a real browser-to-API workflow, install frontend dependencies and Chromium, then run `npm run test:e2e` from `../frontend`. That runner uses a disposable SQLite database and starts its own API server.

## Deployment

Generate a unique application key, configure the database and timezone, run migrations, provision employees, and disable production debug output. Use the web server's Laravel `public/` document root. Serve the SPA and API on the same origin or configure CORS for the intended frontend origin. Keep the AI server on a private interface.

Read [Integration and operations](../docs/INTEGRATION.md) for migration compatibility, legacy-ticket access, configuration, and acceptance criteria.
